    <p>The library includes a dark version of the default theme. It's in <code>style.css</code>, so there's nothing else to import: an attribute on <code>&lt;html&gt;</code> chooses the mode.</p>
    <DocCodeBlock code={DarkModeAttribute} language='html' />
    <p>The simplest setup is <code>system</code>: it follows the operating system's setting with CSS only, so there's no JavaScript, and it works with server-side rendering.</p>
    <p>Every component follows the mode, because they all read their colors from the <code>{'--colors-*'}</code> tokens. Your own CSS follows it too when it uses the tokens. To see it on these pages, use the light / dark toggle in the Storybook toolbar: it sets the same attribute.</p>

    <span className="sub-heading">A toggle that remembers the choice</span>
    <p><code>useColorMode</code> gives the mode the page shows and a function to switch it. The choice is saved in the browser and applied again on the next visit:</p>
    <DocCodeBlock code={DarkModeToggle} language='tsx' title='A dark mode toggle' />
    <ul>
      <li><p><b><code>mode</code></b> is <code>'light'</code> or <code>'dark'</code> (<code>system</code> resolved). <b><code>setMode</code></b> takes <code>'light'</code>, <code>'dark'</code> or <code>'system'</code>, e.g. for a Light / Dark / System select.</p></li>
      <li><p><b>Every component that calls <code>useColorMode</code> shows the same mode</b>, with no provider.</p></li>
      <li><p><b>The saved choice is applied when the hook mounts.</b> If the toggle is only on some pages (e.g. settings), also call <code>useColorMode()</code> in <code>App</code>, or add the script below. On a first visit, the page shows what <code>&lt;html&gt;</code> has: <code>data-rl-color-mode="system"</code> follows the operating system.</p></li>
      <li><p><b>Styles the tokens can't express:</b> in a CSS Module, put the attribute in <code>:global(...)</code>. It stays as it is, and the class is still scoped to the module.</p></li>
    </ul>
